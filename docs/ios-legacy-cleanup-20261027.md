# iOS 旧代码核查与清理 — 2026-10-27

基于 `fc37f88262bdabb28b85fac370ee38fefbb3b467` 继续核查。版本保持
1.104.2，构建号升至 14。本轮候选仅在本地构建，未发布到远端或安装到手机。

## 已确认并修复的问题

1. **IPC 取消和超时任务遗留。** 原 `sendMessage` 忽略调用任务的取消，
   成功后仍保留最长 900 秒的睡眠任务。现在统一处理回复、异常、取消和
   超时，结束时取消实际定时器，晚到回调不能重复完成请求。系统已经接收的
   操作本身没有原生取消接口，此项保证调用方及时结束等待。
2. **排队请求可能切换到新后台。** 原先后台实例在异步任务真正执行时
   才从全局变量取出。现在 App 在主线程捕获实例后才进入后台队列；
   Extension 在生命周期队列上接收请求，固定实例和连接代次。旧请求
   不会重新寻找新后台，旧失败也不能覆盖新连接的错误状态。删除了重复的
   Swift readiness 轮询，直接使用 Go 既有的有期限等待。
3. **HTTP 响应头提交不符合约定。** `WriteHeader` 原先不通知调用方，
   还允许后续写入改掉已经返回的状态码。现在第一个最终状态生效并立即
   通知，重复状态头不能改写结果；正文仍按流读取。
4. **响应未读时遗留资源。** 原先没有可用的关闭接口，`readBody=false`
   会让写正文的处理器继续等待。现在响应有真实 `Close`，Swift 所有请求
   路径都在退出时关闭；读正文异常也执行清理。Go 的 `BodyBytes` 同样释放
   已消费的响应。
5. **上传提前确认和文件流遗漏。** 原先响应与上传错误争抢同一结果通道，
   且提前拒绝、启动失败时没有关闭未开始读取的文件。现在成功必须等待
   所有 multipart 数据写完；提前成功但没有消费文件不能被当作已上传。
   读取错误关闭管道并解除处理器等待，未消费的文件也会关闭。
6. **日志文件泄漏和失败回退崩溃。** 原先只关闭日志器，不关闭持久缓冲区的
   文件句柄；初始化失败还会把 typed-nil 指针装入接口，绕过内存回退。
   现在后台持有并关闭日志缓冲区，初始化成功后才赋给日志配置。

## 已删除的无调用或过期代码

- Swift 全局 packet 注入、重绑包装及对应 stub；实际通路已使用绑定实例的闭包。
- PacketTunnel 旧设置更新入口，以及被 Go readiness 等待替代的轮询和状态包装。
- AppState 的两个旧 AWG 刷新别名、旧 TCP 控制台封装、未使用的错误/偏好刷新助手。
- 仅供旧 TCP 控制台封装使用的两个 Swift 模型；现有 SSH 路径继续使用其独立模型。
- Go 中重复、无调用的单地址/多地址解析包装与旧 `EditPrefs` 管道包装。
- 永远返回 nil 的 `BodyInputStream` 占位接口，替换为真正的响应关闭接口。
- 未使用的错误枚举分支。
- 重复的 `App/Tailscale.entitlements`；签名配置实际引用 `App/AwgScale.entitlements`。
- 已不被构建脚本引用的 `libtailscale/overlays/magicsock_debugknobs_stubs.go`。

清理依据包括全仓引用、协议/系统回调关系和真实构建结果。没有按“名字只
出现一次”直接删除系统 delegate 或 Go/Swift 协议实现，也没有删除用户数据、
旧安装包或历史分支。
